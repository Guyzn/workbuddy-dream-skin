# WorkBuddy Dream Skin

Reversible WorkBuddy desktop theming through local CDP injection. The tool
restarts WorkBuddy with `--remote-debugging-port` (default 9341), discovers its
renderer (`renderer/index.html`), and injects a full-window background art layer,
a Canvas-derived adaptive palette, and frosted-glass panels into the live UI.
No official files are touched.

Unlike simple color-swap skins, Dream Skin adds: focus-point positioning,
safe-area detection, per-route scrim (home vs task), blur/frost, and a
`--watch` daemon that keeps the skin alive across renderer re-renders.

## When this skill applies

- The user gives you a GitHub URL for `Guyzn/workbuddy-dream-skin` (or similar)
  and asks you to install / apply / use it to theme WorkBuddy.
- The user wants to change WorkBuddy's look (color theme, background image,
  custom uploaded image) without editing the official app.
- The user reports the theme disappeared after a WorkBuddy restart and wants it
  reapplied, or wants to revert to the native look.

## Prerequisites

- **WorkBuddy desktop installed** (this tool themes the desktop app, not web).
- **Node.js >= 20** (the injector auto-prefers WorkBuddy's bundled Node, then
  managed binaries, then system node).
- macOS **or** Windows. (Linux is not supported by WorkBuddy's desktop build.)
- Warn the user once: applying **restarts WorkBuddy** and any unsaved in-app
  work is lost. Ask them to save first.

## Platform detection (run first)

- macOS: shell `uname` returns `Darwin`, or `$OSTYPE` starts with `darwin`.
- Windows: PowerShell `$IsWindows` is `$true`, or `$env:OS` is `Windows_NT`.
- Choose the matching branch below.

## Workflow — macOS

1. Clone / open the repo, then install (writes state under
   `~/Library/Application Support/WorkBuddyDreamSkinStudio` and seeds presets):

   ```bash
   cd macos
   ./scripts/install-dream-skin-macos.sh --no-launch
   ```

2. Start the skin (restarts WorkBuddy once to open the CDP port; `--prompt-restart`
   shows a confirmation dialog first):

   ```bash
   ./scripts/start-dream-skin-macos.sh --prompt-restart
   ```

   Desktop launchers are also generated:
   - `WorkBuddy Dream Skin.command` — apply / re-apply
   - `WorkBuddy Dream Skin - Customize.command` — import your own background
   - `WorkBuddy Dream Skin - Verify.command` — verify injection
   - `WorkBuddy Dream Skin - Restore.command` — restore native (restarts WorkBuddy)

3. Verify:

   ```bash
   ./scripts/verify-dream-skin-macos.sh
   ./scripts/status-dream-skin-macos.sh
   ```

   Expect an active state and the WorkBuddy renderer listed.

4. Optional menu bar (needs [SwiftBar](https://swiftbar.app)):

   ```bash
   ./scripts/install-menubar-macos.sh
   # A 🎨 Skin menu appears in the menu bar: apply / pause / switch preset / import / diagnose
   ```

## Workflow — Windows

1. From the repo, run in **PowerShell** (not cmd):

   ```powershell
   cd windows\scripts
   powershell -ExecutionPolicy Bypass -File .\install-dream-skin.ps1
   powershell -ExecutionPolicy Bypass -File .\start-dream-skin.ps1
   ```

2. Optional system tray (right-click icon to operate):

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\tray-dream-skin.ps1
   ```

3. Verify:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\verify-dream-skin.ps1
   ```

4. If `start-dream-skin.ps1` cannot locate WorkBuddy.exe or the CDP port never
   becomes ready, run the locator and follow its printed hints:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\find-workbuddy.ps1
   ```

## Choosing a theme

- List presets:
  ```bash
  ./scripts/status-dream-skin-macos.sh          # shows applied theme
  ls macos/presets/                             # bundled preset ids
  ```
- Built-in presets: `preset-aurora-dusk` (Aurora Dusk), `preset-midnight-bloom`
  (Midnight Bloom), `preset-ember-zen` (Ember Zen). All backgrounds are
  programmatically generated by `macos/scripts/gen_presets.py` — no third-party
  assets.
- Switch preset:
  ```bash
  ./scripts/switch-theme-macos.sh --id preset-aurora-dusk
  # Windows: .\switch-theme-windows.ps1 -Id preset-aurora-dusk
  ```
- Import your own clean background (recommend 2560x1440, <=16MB, no UI/text/watermark):
  ```bash
  ./scripts/customize-theme-macos.sh --image "/path/to/bg.jpg" --name "My Skin" --accent "#3fd6a6"
  ```

## Pause / restore to native

```bash
# macOS
./scripts/pause-dream-skin-macos.sh      # stop injection, keep WorkBuddy as-is
./scripts/restore-dream-skin-macos.sh    # remove injection AND restart WorkBuddy normally

# Windows (PowerShell)
.\pause-dream-skin.ps1
.\restore-dream-skin.ps1
```

The official install is always left untouched.

## Diagnostics

```bash
./scripts/doctor-macos.sh          # dumps live renderer: rootClass/themeName/colorScheme/hasMonaco
./scripts/verify-dream-skin-macos.sh

# Direct injector probes:
cd macos/scripts
node injector.mjs --inspect --port 9341      # live DOM probe JSON
node injector.mjs --check-payload            # validate a theme payload builds
node injector.mjs --restore --port 9341      # cleanup only (no restart)
```

`doctor` should report the correct platform, a found WorkBuddy app, and the
renderer hint `renderer/index.html`.

## Guardrails

- Never replace, edit, or take ownership of `WorkBuddy.app`, `app.asar`, or the
  Windows install directory. This tool only injects into the live renderer.
- CDP binds to loopback `127.0.0.1` only. Tell the user not to run untrusted
  local software while a skin is active (Chromium CDP has no same-user auth).
- Injection is kept alive by a `--watch` daemon (launchd job on macOS). After a
  **manual** WorkBuddy restart the skin disappears by design — re-run
  `start-dream-skin-macos.sh` (hot path: CDP already open, re-applies without a
  full restart) to bring it back.
- Do not import README/preview screenshots or images with baked-in UI as a
  theme background; use clean wallpapers.

## Checks (sanity before reporting done)

```bash
./scripts/doctor-macos.sh           # platform, app path, CDP port, renderer probe
./scripts/verify-dream-skin-macos.sh
node --check macos/scripts/injector.mjs   # syntax
```

`doctor` should report the correct platform, a found WorkBuddy app, and the
renderer hint `renderer/index.html`.
